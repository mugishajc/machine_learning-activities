  total transactions 15,000   actual fraud 150 (1.000%)
  note: the question states a background fraud rate of about 3%, but the matrix
  itself gives 150/15000 = 1.00%. All figures below follow the matrix,
  since that is the evidence supplied. The discrepancy is noted, not resolved.
  flagged 570 (3.800% of all traffic)

==============================================================================
2. METRICS, SHOWN AS ARITHMETIC
  precision   = TP / (TP + FP) = 120 / (120 + 450) = 120/570 = 0.2105  (21.05%)
  recall      = TP / (TP + FN) = 120 / (120 + 30) = 120/150 = 0.8000  (80.00%)
  specificity = TN / (TN + FP) = 14400 / (14400 + 450) = 14400/14850 = 0.9697  (96.97%)
  F1          = 2PR/(P+R) = 2(0.2105)(0.8000) / (0.2105 + 0.8000) = 0.336842 / 1.010526 = 0.3333

  for contrast, accuracy = (TP+TN)/N = (120+14400)/15000 = 0.9680 (96.80%)
  a model predicting 'legitimate' for everything would score 0.9900 (99.00%) and catch no fraud at all

==============================================================================
3. QUESTION FOUR(a): THE 2% CASE, WORKED
  with a 2% fraud rate, the all-legitimate classifier gives:
    accuracy    = TN/N = 0.98 = 98%
    recall      = TP/(TP+FN) = 0 / (0 + 0.02N) = 0
    precision   = TP/(TP+FP) = 0/0, undefined and conventionally reported as 0
    F1          = 0
  on 100,000 transactions that is 98,000 correct and 2,000 frauds missed, every one of them.

  raising the threshold demands more confidence before flagging, so fewer alerts
  are raised: false positives fall, precision rises, false negatives rise and
  recall falls. The two move in opposite directions by construction.
